# Employee Loans / Advances Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HR records an employee loan/advance with a fixed installment; each payroll run deducts the installment once, reduces the balance, and closes the loan at zero.

**Architecture:** One active loan per employee. The payroll runner reads active loans for the run period, adds `loan_deduction` to the immutable payroll input, deducts it in the DAG after SSO/tax/PF, and records a `loan_installments` row + balance decrement in the same transaction as the payslip. The unique `(loan_id, payroll_run_id)` makes re-runs idempotent.

**Tech Stack:** Rust/Axum/SQLx, `talentos-payroll` DAG, payroll runner, Next.js 15.

**Spec:** `docs/superpowers/plans/2026-10-27-competitive-gap-roadmap.md` (Phase 4: salary advances and loans with installment deductions).

## Global Constraints

- Money is `Decimal`; loan deduction cannot make net pay negative (existing DAG error).
- One active loan per employee; installment > 0; principal > 0; balance never below zero.
- Deduct once per (loan, run); re-running/reqeueuing a payroll run does not double-charge.
- Only HR (`employee.update`) creates/cancels; employees can read their own loans; tenant RLS everywhere.
- Payslip gains `loan_deduction`; total deductions/net reflect it; render shows the line.
- No change to tax/SSO/PF math beyond subtracting the loan from net.
- No production unwrap/expect; Thai UI; `cargo fmt/clippy/test`, `npm run build`, Playwright 18/18.

## Review Focus

- **Idempotency:** rerunning a payroll run does not create a second installment or reduce the balance twice.
- **Cap:** the deduction is `min(installment, balance)`; a final payment closes the loan.
- **Failed payslips:** an employee whose pay fails gets no installment/balance change.
- **Negative net:** an oversized installment fails that employee's payslip cleanly.
- **Concurrency:** two runs cannot both deduct the same loan installment (unique key + transaction).
- **GL/report:** loan deduction is a credit line or reduces net; the journal stays balanced.
