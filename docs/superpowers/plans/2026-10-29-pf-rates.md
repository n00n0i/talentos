# PF Rate History Plan

**Goal:** PF contribution rates are effective-dated per employee; payroll uses the rate effective at the run period end (default 5%).

## Files
Migration `pf_rate_history`; `hr-runner/src/pf.rs`; payroll runner input; employee PF-rate endpoints; employee edit UI; tests.

## Schema
`pf_rate_history(id BIGSERIAL, tenant_id, employee_id, effective_from DATE, rate NUMERIC(5,4) CHECK (rate BETWEEN 0 AND 0.15), created_by, created_at, UNIQUE(tenant_id, employee_id, effective_from))`, RLS FORCE.

## Rules
- `rate_for(employee, as_of)` = latest `effective_from <= as_of`, else 0.05.
- Payroll runner uses `rate_for(employee, period_end)` instead of the fixed 5% (only when `pf_member`).
- `GET/POST /api/v1/employees/:id/pf-rates` (`employee.read_all`/`employee.update`): POST `{effective_from, rate}` upserts that date; rate is a decimal fraction (0.05 = 5%), reject >0.15/negative.
- Employee edit UI: “อัตรา PF (%)” + “มีผลตั้งแต่” fields; saving posts to the PF-rate endpoint and reloads; current rate shown.
- No change to PF base, employer match, or GL.
- Provider API remains out of scope.

## Tests
Default 5%; rate effective by date; future rate not used; payroll integration uses period-end rate; validation bounds; tenant scope.
