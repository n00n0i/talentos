# Prometheus Metrics & Alerting Plan

**Goal:** Expose gateway HTTP metrics in Prometheus text format so operators can alert on error rate and latency, without adding a metrics dependency.

## Implementation
- `crates/api/gateway/src/metrics.rs`:
  - `Metrics` counters: total requests, 2xx/4xx/5xx, duration sum/count, start instant.
  - `track(req, next)` middleware records every response.
  - `render()` emits:
    - `talentos_http_requests_total{status="2xx|4xx|5xx"}`
    - `talentos_http_request_duration_seconds_sum|_count`
    - `talentos_uptime_seconds`
  - Global `METRICS: Lazy<Metrics>`.
- `GET /metrics`:
  - public when `METRICS_TOKEN` is unset (bind behind the private network/proxy);
  - when set, require `Authorization: Bearer <token>`, else 401.
- Router: add `middleware::from_fn(metrics::track)` and the route.
- `/metrics` itself is counted (harmless).

## Tests / verification
- Unit: counters and Prometheus rendering include status classes, duration, uptime; token check is covered by an extractor helper? Keep token logic in the handler and document manual verification.
- CI `e2e` job: after health, `curl -sf .../metrics | grep talentos_http_requests_total`.
- Local: curl `/metrics` after requests.
- Gates: fmt/clippy/tests/build, Playwright unchanged (47/47).

## Docs
`docs/ops/metrics.md`: scrape config, example alert rules (5xx ratio > 5% over 5m, average latency > 1s over 5m), and a note that DB/outbox business gauges are not exposed yet.

## Out of scope
- No per-route histograms (cardinality control), no tracing export, no Grafana dashboards, no alert receiver config.
